# 多维天气标尺 + 混沌系统（设计方案，未实现）

> 这份是**方案**不是实现记录。`docs/NOTES.md` 记的是已落地的东西踩了什么坑，
> 这里记的是"打算怎么做、为什么这么做"。实现之后应该把它并进 NOTES。

## 起点：用户的两条意见

1. **多维展示**：现在只有一个合成指数（WXI）。
   真实交易市场可以换个维度看 —— **气温、风速、湿度**这些本身就是"价位"，
   应该能分别看到它们**站在上升还是下降那边、以及幅度多大**。
2. **混沌系统**：突然的变化交给一个叫「混沌系统」的角色驱动，
   甚至可以往里埋彩蛋。

## 第 1 部分：多维标尺

### 现状

`severity()` / `comfort()` 把六个分量（体感温度、露点、降水、天气码、阵风、PM2.5）
**加权压成一个数**。压完之后就再也分不开了 —— 用户看到指数跌 3%，不知道是
"降温了"还是"下雨了"还是"起风了"。

### 目标形态

不是各画一条价格线（那会变成六个互不相关的标的，和"天气指数"这个设定脱节），
而是**一个"压力表"面板**，每个分量一行：

```
  维度        当前值      近 7 天分位    方向     对指数贡献
  ────────────────────────────────────────────────────────
  气温        31.4 ℃        88%          ↑        −6.2 点
  露点        26.1 ℃        93%          ↑        −4.1 点
  降水         0.8 mm        71%          ↑        −9.8 点   ← 主导
  阵风        31.3 km/h      84%          ↑        −2.0 点
  天气码        95 雷暴       97%          →       −12.4 点   ← 主导
  空气        36.1 µg        52%          ↓        +0.8 点
  ────────────────────────────────────────────────────────
  合计                                              −33.7 点
```

**关键点：最后一列必须能真的加总到指数变化上。**
否则它就是六行装饰性的数字，玩家看两次就不看了。
做法是把 `comfort()` 拆成"每维度的贡献"再求和，而不是只返回加权总分：

```js
comfortParts(mn, pm25) → [{ key:'temp', v:31.4, score:52, contrib:-6.2 }, ...]
```

这样 `comfort()` 变成 `sum(parts.contrib)`，**两条路径共用一份计算**，
不会出现"面板说的"和"指数走的"对不上。

### 为什么用"分位"而不是绝对值

"31.4 ℃"玩家没有直觉。但"近 7 天 88% 分位"立刻能懂 ——
**和真实行情里"RSI 88"是一回事**。所以每一维都要给出它在本局窗口内的百分位。

### 落在哪里

右栏"天气日历"下面加一个折叠区（默认展开，占 ~8 行）。
和日历的分工：日历说**未来什么时候会变**，压力表说**现在是什么状态**。

## 第 2 部分：混沌系统

### 为什么需要它

现在的"突发变化"有两个来源，都不够劲：

| 来源 | 现状 | 问题 |
|---|---|---|
| `JUMP_AT` 跳变 | `\|Δseverity\| > 1.8` 触发，每局约 9.6 次 | 是**被动**的 —— 天气变了才有，天气平稳就一次没有 |
| 插针 | 每局 1.4 次，已实现 | 只改影线、不改收盘，是**视觉**事件不是**行情**事件 |

缺的是一个**主动的**、能把行情真正推起来的东西 —— 也就是用户说的"混沌系统"。

### 设计：三层

```
混沌系统 = 触发层（什么时候乱）+ 形态层（怎么乱）+ 叙事层（为什么乱）

触发层：不只看"天气变没变"，还看**系统自身的状态**
        · 波动率聚集：最近 N 根的波动越大，越容易再来一次（真实市场就是这样）
        · 过热回归：指数偏离基本面越远，越容易被拉回来（本来有 REVERT，但可以更猛）
        · 天气事件：台风/地震/雷暴已经在做了
形态层：五种基本形态，每种给不同的 OHLC 形状
        · 插针     长针 + 立刻收回（已实现）
        · 瀑布     连续 3~5 根同向大实体（carry 已在做，可以更结构化）
        · 假突破   先破关键位再收回，专门扫止损
        · 横盘后暴动 长时间极低波动，然后一根巨量
        · 闪崩回补 一根打到底，下一根收回大半
叙事层：每次混沌事件给一句话原因，从真实数据里挑
        · "雷暴过境，成交骤停"（wcode=95/96）
        · "台风外围环流抵达"（typh 项 > 0）
        · "能见度骤降，运力受限"（PM2.5 突增）
        · "震感传来，避险情绪升温"（quake 项）
```

### 状态机，不是概率表

重点是**触发层要记住上一步的状态**（波动率、偏离度），
而不是每根独立掷骰子。否则会变成"均匀撒点"，没有"平静越久、爆发越猛"的节奏感 ——
而那正是真实市场最好玩的地方。

```js
chaos = {
  heat: 0,          // 热度：最近波动的 EMA，越高越容易触发
  calm: 0,          // 平静度：连续低波动根数，越高越容易"憋出"一次暴动
  lastAt: -999,     // 上次混沌事件的位置（避免连续触发）
  form: null        // 当前正在演出的形态（瀑布/假突破要跨好几根）
}
```

### 彩蛋（先留接口，具体内容后说）

叙事层留一个 `egg(seed, city, time)` 的钩子，按**确定的输入**（城市哈希 + 时间 + 天气）
触发，所以：
- 同一个城市、同一段天气，彩蛋每次都一样（可复现，探针能测）
- 不写死在代码里"第 3 天出现"，而是从真实数据里长出来

用户说"彩蛋后面再说"，所以这一层**先只留接口和注释**，不实现内容。

## 实现顺序（建议）

1. **`comfortParts()` 重构** —— 把 `comfort()` 拆成可加总的分量。
   这一步不动任何数值结果（`comfort()` = 各分量之和），所以是纯重构，
   可以用"重构前后 comfort 逐点相等"来验收。
2. **多维压力表面板** —— 纯展示层，数据来自第 1 步。
3. **混沌系统：触发层 + 状态机** —— 这一步会**改变行情分布**，
   必须重新跑 `tools/check_comfort_model.js` 和 `tools/solve_comfort_model.js`
   确认波动水平没被推离靶子。
4. **混沌系统：形态层** —— 插针已实现，补瀑布/假突破/闪崩。
5. **叙事层 + 彩蛋接口** —— 最后做。

## 验收标准（先定，免得又变成"感觉不对"）

| 项 | 靶子 |
|---|---|
| 中位 \|涨跌\| | 0.1848%（真实交易所） |
| lag-1 自相关 | 越低越好，当前 0.383 |
| 插针频率 | 每局 1~3 次 |
| 插针形态 | 影线/实体 > 8 |
| 混沌事件 | 每局 3~6 次，且**不是均匀分布**（平静越久越容易爆发） |
| 面板加总 | 各维度贡献之和 === 指数变化，误差 < 0.01% |
